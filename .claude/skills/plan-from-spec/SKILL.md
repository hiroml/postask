# 実装計画の作成

## 前提チェック

1. 対象の仕様書（引数で番号指定、なければユーザーに確認）を読む。
2. frontmatter が `status: approved` でなければ**中断**し、承認が必要であることをユーザーに伝える。
3. 未決事項に未チェックの項目が残っている、または `docs/questions.md` の「回答待ち」にこの仕様に関連する 🔴 の項目があれば、中断して回答を依頼する。

## 手順

1. 関連する既存コードを調査する（`src/`, `src-tauri/src/`）。
2. `docs/plans/_template.md` をコピーして `docs/plans/NNN-<仕様書と同じ名前>.md` を作る。
3. タスクに分解する。
   - 1タスク = 1コミットで完結し、単独でビルドが通る粒度
   - 依存順（DB → コマンド → UI → 確認）に並べる
   - 各タスクに対象ファイルを書く
   - 仕様の受け入れ条件（AC）のどれに対応するかを書く
4. テスト方針とリスクを書く。
5. 新しい依存クレートや DB スキーマ変更が必要なら「リスク・懸念」に明記する。
6. 計画ファイルを `main` に commit する（例: `docs(001): 実装計画を作成`）。

## 完了時の報告

タスク一覧と、人に確認が必要なリスクがあればそれを伝える。
