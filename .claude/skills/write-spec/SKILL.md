# 仕様書ドラフトの作成

## 手順

1. `docs/project/overview.md`、`docs/project/glossary.md`、`docs/project/architecture.md` を読み、前提を把握する。
2. `docs/specs/` の既存ファイルを確認し、次の連番（3桁、例: `002`）を決める。
3. 要望があいまいな場合は、書き始める前に**最大3問まで**ユーザーに質問する（目的・対象範囲・優先度など）。
4. `docs/specs/_template.md` をコピーして `docs/specs/NNN-kebab-case-name.md` を作る。
5. 各セクションを埋める。
   - 受け入れ条件は「〇〇のとき、〇〇となる」形式で、人が実際に触って確認できる粒度にする。
   - 用語は用語集に合わせる。新しい用語があれば用語集にも追加する。
   - 判断できない点は推測で埋めず、`docs/questions.md` の「回答待ち」に次の番号（Q-NNN）で追加する。
     背景・選択肢・AI の推奨・優先度を書き、`回答:` は空欄にする。仕様書の「未決事項」にはリンクだけを置く。
6. 関連コードを読み、「データ・API」に DB 変更と Tauri コマンドの案を書く。
7. 書き終えたら `status: review` にする。
8. 仕様書・判断待ちボード・用語集の変更を `main` に commit する（例: `docs(002): 仕様書ドラフトを作成`）。

## 完了時の報告

- 作成したファイルへのリンク
- 要件の要約（3行程度）
- 追加した確認事項の ID と要点（回答は `docs/questions.md` に書いてもらう）
- 「回答後に `/apply-answers` で反映します。未決事項がなくなったら `status: approved` に変更してください」と伝える

## 禁止事項

- `status` を `approved` / `done` に変更しない（人のみが行う）
- 仕様書作成中に実装コードを書かない
