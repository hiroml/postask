# 確認依頼の作成

## 手順

1. 仕様書・計画ファイルを読み、全タスクが完了しているか確認する。
2. 検証を実行し、結果を記録する。

   ```sh
   cargo fmt --all --check
   cargo clippy --workspace -- -D warnings
   cargo test --workspace
   ```

3. `spec-reviewer` サブエージェントに、仕様書と実装の突き合わせを依頼する。
4. `docs/reviews/_template.md` をコピーして `docs/reviews/NNN-<仕様書と同じ名前>.md` を作る。
5. 各セクションを埋める。
   - 受け入れ条件ごとに結果と確認方法を書く。AI が確認できず人の手動確認が必要なものは ⚠️ にする
   - 「人に確認してほしいこと」には、仕様から外れた点・AI が判断した点・トレードオフを**正直に**書く。
     回答（決定）が必要なものは `docs/questions.md` にも追加し、ID でリンクする
   - 「動作確認手順」は、人がそのまま操作できる具体的な手順にする
6. 「人のレビュー欄」は空欄のまま残す。
7. 確認依頼ファイルを実装ブランチに commit する（例: `docs(001): 確認依頼を作成`）。
8. 人が approved にして「マージして」と言ったら、`main` に `git merge --no-ff feat/NNN-名前` でマージする。

## 完了時の報告

確認依頼ファイルへのリンクと、人に特に見てほしい点を伝える。
`docs/reviews/checklist.md` のゲート2を使って確認するよう案内する。

## 禁止事項

- レビューの `status` を `approved`、仕様書を `done` にしない（人のみが行う）
- 失敗した検証を成功と書かない
