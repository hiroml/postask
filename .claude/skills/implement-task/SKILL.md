# タスクの実装

## 手順

1. 対象の計画ファイルと、紐づく仕様書を読む。仕様書が `approved` でなければ中断する。
2. 未完了（`- [ ]`）の先頭タスクを選ぶ（ユーザーの指定があればそれ）。
   - 実装ブランチ `feat/NNN-名前` にいることを確認する。無ければ `main` から作って切り替える。
3. 実装する。
   - 仕様書に書かれていない振る舞いは追加しない
   - 仕様と実装が食い違う・仕様に不備があると気づいたら、実装を止めて `docs/questions.md` に確認事項を追加し、ユーザーに報告する
   - CLAUDE.md の「人に確認すべきこと」に該当する変更は事前に確認する
4. テストを書く（Tauri コマンド・ロジックは単体テスト必須）。
5. 検証を実行する。

   ```sh
   cargo fmt --all
   cargo clippy --workspace -- -D warnings
   cargo test --workspace
   ```

6. すべて通ったら、計画ファイルのタスクを `- [x]` にし、作業ログに1行追記する。
7. 新しい Tauri コマンドを追加した場合は `docs/project/architecture.md` のコマンド一覧を更新する。
8. CLAUDE.md の「Git 運用」に従い、コードと計画ファイルの更新をまとめて1コミットにする（例: `feat(001): T2 create_post コマンドを追加`）。検証が失敗しているときは commit しない。

## 完了時の報告

- 実装内容と変更ファイル
- 検証結果（失敗があればそのまま出力を示す）
- 残りタスク数。全タスク完了なら `/request-review` を提案する
