# バックログの整理

## 受付箱の処理・項目の追加

1. `docs/backlog.md` を読む。
2. 「受付箱」の各行（またはユーザーの発言）を1件ずつ「一覧」に登録する。
   - ID は既存の最大番号の次（B-NNN）
   - 種別（機能 / 改善 / バグ / 技術）・優先度を判断して付ける。迷ったら備考に「要確認」と書く
   - 起票は、受付箱・ユーザー発言なら `人`、AI が見つけたものなら `AI`
   - 既存の項目と重複する場合は新規に作らず、既存項目の備考に追記する
   - バグは「何をしたら・どうなった・どうなるべきか」が分かるように備考に書く。足りなければユーザーに聞く
3. 登録した行を受付箱から消す。
4. 決定が必要な論点があれば `docs/questions.md` にも追加し、備考からリンクする。

## 次のバッチの提案

1. 「今回のバッチ」が空いている（または全件完了した）ことを確認する。
2. 一覧から、次の観点で3件を提案する（理由を1行ずつ付ける）。
   - 優先度が高い / 他の項目の前提になる（例: マイグレーションは列追加の前に必要）
   - 同じ仕様書にまとめられる、または同じ場所を触るものは一緒にやると効率が良い
   - 大きいもの1件＋小さいもの2件のように、作業量の偏りに注意する
3. **選ぶのは人**。承認されたら「今回のバッチ」に入れ、状態を更新する。
4. バッチの進め方: 仕様書が必要なものは `/write-spec`、小さな技術課題・バグ修正は仕様書なしで直接実装してよい（CLAUDE.md のルールどおり）。

## 状態の更新

- 仕様書を作ったら `仕様化`、実装ブランチを切ったら `実装中`、確認依頼を出したら `確認待ち`
- main にマージしたら「一覧」から消して「完了」に移し、「今回のバッチ」からも外す
- 変更したら commit する（例: `docs: バックログに B-015〜B-017 を追加`）
