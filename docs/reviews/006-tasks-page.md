## 人に確認してほしいこと

1. **集計の方法を変えた（仕様との違い）**: 仕様では「SQL の GROUP BY で集計」としていましたが、日付の区切りをパソコンのタイムゾーン（日本時間）で正しく数えるため、タスクを SQL でまとめて読んで Rust で集計しています（バックエンドで集計する点は同じ）。1,000件程度なら問題ない速さの見込みです。
2. **横棒は HTML、折れ線は SVG**: どちらもライブラリを使わず自前で描いています（Q-025）。横棒は文字の表示がきれいな HTML の方が向いていたため、HTML の要素で描いています。
3. **一覧の完了チェックとホーム**: ホームに読み込み済みのポストは、ホームの表示も更新します。まだ読み込んでいない古いポストは、ホームのタイムラインに勝手に足しません（「さらに読み込む」の位置がずれるため）。ホームで「さらに読み込む」を押せば、正しい状態で出ます。
4. **自動の取り直し**: タイムラインが変わったとき（新しいポストの分類完了、ホームでの完了など）に、課題ページの集計も取り直します。
5. **「課題」のチップの赤**: 一覧の種別チップは今までどおりの色です。赤が「エラー」と紛らわしい件はバックログ B-030 で扱います。

## 動作確認手順（人向け）

開発用 DB（あなたの普段のデータのコピー）で確認できます。

1. `cargo tauri dev` を起動し直し、メニューの「✅ 課題」を開く → 数字・棒・折れ線・一覧が出る（**AC-1**）
2. 数字の「未完了＋完了」と「課題の一覧（N件）」が一致する（**AC-2**）
3. 期間・種別・状態を変える → すべてそろって変わる（**AC-3**）
4. 棒の「調査」などをクリック → 種別が切り替わる（**AC-4**）
5. 棒・折れ線にマウスを乗せる → 値が出る。折れ線をクリックしてから左右キーでも動く（**AC-5**）
6. 「表で見る」→ 同じ数字の表（**AC-6**）
7. 一覧で ○ をクリック → 未完了が1減り完了が1増える → ホームに戻ると、そのタスクが完了になっている（**AC-7**）
