# 人のレビュー用チェックリスト

AI の成果物を確認するときの観点です。

## 仕様書の承認時（ゲート1）

- [ ] 目的・背景が自分の意図と一致している
- [ ] 受け入れ条件が具体的で、確認可能な形になっている
- [ ] スコープ外が明記されている
- [ ] 未決事項がすべて解消されている
- [ ] DB 変更・新しい依存・セキュリティ設定変更の有無を把握した

→ OK なら frontmatter を `status: approved`、`approved_by` に名前を記入

## 実装の確認時（ゲート2）

- [ ] 受け入れ条件をすべて満たしている（実際にアプリで触って確認）
- [ ] 仕様にない振る舞いが追加されていない
- [ ] テストが意味のある内容になっている（通すだけのテストでない）
- [ ] `unwrap()` の乱用やエラーの握りつぶしがない
- [ ] 「人に確認してほしいこと」に回答した

→ OK ならレビューを `status: approved`、仕様書を `status: done` に変更し、AI に「マージして」と伝える（実装ブランチが `main` に入る）
