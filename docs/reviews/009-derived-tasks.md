# 009: 関連タスクの派生 — 確認依頼

## 変更概要

タスクから「関連するやること」を派生ポストとして投稿できるようにしました。作り方は2通りです（Q-031）。

- **手動**: タスクチップの「↳」で、ポストの下に入力欄が開く
- **AI の提案から**: AI リプライの下の「↳ ここから関連タスクを作る」で候補（最大5件）が出る。チェックして直して投稿する

派生ポストには「↳ 〇〇 から」が付き、元のタスクのチップには「↳ 完了数/子の数」、すべて完了すると「✓ 関連タスク完了」が出ます。親と子の完了は連動しません（Q-032）。

## 人に確認してほしいこと

1. **AC-2 と AC-5 の食い違い（仕様の直し）**: AC-2 は「子を完了にすると『↳ 1/1』になる」ですが、子が1件だけのときはそれで「すべて完了」になるため、FR-8・AC-5 に従って「✓ 関連タスク完了」と出ます。「↳ 1/1」は子が2件以上で一部完了のとき（例「↳ 1/2」）に出ます。こちらの動きでよければ、AC-2 の文を「子を完了にすると『✓ 関連タスク完了』になる（子が複数なら『↳ 1/2』）」に直します。
2. **「↳」ボタンはメニューを挟まない**: 仕様は「↳ ボタンから『関連タスクを投稿』を選ぶ」ですが、選べるものが1つなので、ボタンを押すとすぐ入力欄が開くようにしました（ボタンの説明に「関連タスクを投稿」と出ます）。
3. **入力欄と候補の欄は一度に1つ**: 別のタスクで「↳」を押すと、前の入力欄は閉じます（書きかけの文も消えます）。候補の欄も同じです。
4. **ホームの一覧の描き方を変えた**: 今までは何かが変わるたびに全ポストを描き直していたため、派生の入力中に別のポストの分類が終わると、入力欄が消えてしまいます。ポストごとに描き、変わったポストだけを描き直すようにしました。
5. **DB の更新（版5）**: 開発用 DB は起動時に版5になります（データは消えません）。
6. **候補の料金**: 候補はボタンを押したときだけ、リプライと同じモデルで1回呼びます。

## 動作確認手順（人向け）

1. `cargo tauri dev` → 「READMEを書く」などのポストを作り、タスクチップの「↳」を押す → ポストの下に入力欄が開く。Esc で閉じる（**FR-1, FR-4**）
2. もう一度開いて「ライセンスの種類を調べる」とポスト → 「↳ READMEを書く から」付きで出て、分類されてタスクができる（**AC-1**）
3. 元のチップに「↳ 0/1」→ 子を完了にすると「✓ 関連タスク完了」、元のタスクは未完了のまま。元を完了にしても子は変わらない（**AC-2, AC-5**）
4. 派生したタスクの「↳」からさらに派生できる（**AC-3**）
5. 「✅ 課題」ページの一覧で、子に「↳ 元のタスク名」、親に子の数が出る（**AC-4**）
6. 「ログイン画面のバリデーションを直す」とポストして「🤖 AI に聞く」→ リプライの下の「↳ ここから関連タスクを作る」→ 候補が出る。2つにチェックして（文を直してもよい）「2件を投稿」→ 派生ポストが2つでき、元のチップが「↳ 0/2」（**AC-7**）
