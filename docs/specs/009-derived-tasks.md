# 009: 関連タスクの派生

## 背景・目的

タスクに取り組むと、「そのためにまず〇〇を調べる」「ついでに〇〇も直す」のように、関連するタスクが生まれる。
今はそれを普通のポストとして書くしかなく、元のタスクとのつながりが失われる。

コンセプトの「タスクに関するタスクは紐づけして、新しいタスク（投稿）として起こす」（overview F5、B-002）として、
**タスクから派生したポストを投稿し、そこから生まれたタスクを元のタスクの子として紐づける**。

B-019（リプライ・リツイート）のうち「自身の課題から派生した課題について投稿できる」部分にあたる。

## ユーザーストーリー

- ユーザーとして、あるタスクから「関連するやること」をその場でポストしたい。
- ユーザーとして、派生したタスクが、どのタスクから生まれたか分かるようにしたい。
- ユーザーとして、元のタスクに関連タスクがいくつあって、いくつ終わったかを見たい。

## 要件

### 派生ポストを投稿する

- [ ] FR-1: 派生の作り方は Q-031 の回答に従う。推奨案では、タスクチップのメニュー（または「↳」ボタン）から「関連タスクを投稿」を選ぶと、そのポストの下に小さな入力欄が開き、投稿できる。
- [ ] FR-2: 派生ポストは普段のポストと同じく保存・分類される（仕様001）。そこから生まれたタスクは、元のタスクの **子** になる。
- [ ] FR-3: 派生ポストもタイムラインに出す。本文の上に「↳ 〇〇（元のタスクのタイトル）から」と表示する。
- [ ] FR-4: 入力欄は280文字まで（仕様001と同じ）。Esc で閉じる。

### 表示

- [ ] FR-5: 子のあるタスクのチップに、子の数と完了数を「↳ 1/3」のように表示する。
- [ ] FR-6: 課題ページの一覧（仕様006）で、子のあるタスクに同じ表示を出す。子のタスクには「↳ 元のタスク名」を出す。
- [ ] FR-7: 親子は何段でもつなげられる（子からさらに派生できる）。表示は直前の親だけ。

### 完了との関係

- [ ] FR-8: 親と子の完了の関係は Q-032 の回答に従う（推奨: 連動しない。子がすべて完了したら、親のチップに「✓ 関連タスク完了」と出すだけ）。

### 非機能要件

- NFR-1: 元のタスクが消えても（今は分類の再試行などで起きうる）、派生ポストとそのタスクは残る（親のつながりだけ消える）。

## 受け入れ条件

- [ ] AC-1: 「READMEを書く」タスクから「ライセンスの種類を調べる」を派生ポストすると、タイムラインに「↳ READMEを書く から」付きで出て、「調査」のタスクができる。
- [ ] AC-2: 元の「READMEを書く」のチップに「↳ 0/1」と出る。子を完了にすると「↳ 1/1」になる。
- [ ] AC-3: 派生したタスクから、さらに派生できる。
- [ ] AC-4: 課題ページの一覧で、親と子の表示が出る。
- [ ] AC-5: 親子の完了の関係が Q-032 の回答どおりになる。
- [ ] AC-6: 親子のつながりの保存・数え方の単体テストが通る（子の数・完了数、親が消えたとき）。

## 画面・UI

```
│ READMEを書く、あとCIも設定する                      │
│ [○ 課題 | READMEを書く ↳ 0/1 ⋯]  [○ 課題 | CIを設定する ⋯] │
│   ┌ ↳ 「READMEを書く」に関連するタスク ──────────┐    │
│   │ ライセンスの種類を調べる                      │    │
│   │                     [キャンセル] [ポスト]    │    │
│   └──────────────────────────────────────┘    │

│ ↳ READMEを書く から                                 │ ← 派生ポスト
│ ライセンスの種類を調べる                             │
│ [○ 調査 | ライセンスの種類を調べる]                   │
```

## データ・API

### DB（マイグレーション 版5。008 の版4 の後）

```sql
ALTER TABLE posts ADD COLUMN parent_task_id INTEGER REFERENCES tasks(id) ON DELETE SET NULL;
CREATE INDEX idx_posts_parent_task_id ON posts(parent_task_id);
```

- 親子は「派生ポスト → 元のタスク」で持つ。派生ポストのタスクが、元のタスクの子になる。
- 子の数・完了数は、`posts.parent_task_id = 親の id` のポストに付いたタスクを数える。

### Tauri コマンド

- `create_post(body, parent_task_id: Option<i64>)`: 既存のコマンドに `parent_task_id` を足す（無ければ今までどおり）。存在しないタスク id はエラー。
- `PostWithTasks` に `parent: Option<{ task_id, title }>` を、`Task` に `children: { total, done }` を足す。
- 課題ページの `TaskRow` にも同じ情報を足す。

## 注意点

- 分類の再試行（`retry_classification`）はタスクを作り直すため、元のタスクが作り直されると親子のつながりが消える（NFR-1）。再試行できるのは分類に失敗したポスト（タスクが無い）だけなので、今は問題にならない。今後タスクを作り直す機能（B-004 など）を作るときは、つながりを引き継ぐ必要がある。

## スコープ外

- AI が派生タスクを提案する（AI リプライの「最初のステップ」をタスクにするボタンなど。Q-031 で C を選んだ場合は範囲に入れる）
- 親子のツリー表示（全体を木の形で見る）
- 既存のポストを後から親に紐づける
