# 007: 種別の色とチップの見直し

## 背景・目的

タスクの種別（課題・思い付き・調査）は、チップの色で見分けている。今の色には次の問題がある（dataviz スキルの検証スクリプトで確認）。

| 問題 | 詳細 |
| --- | --- |
| 「課題」が赤 | 赤は一般に「エラー・危険」を表す色。種別の色としては紛らわしい |
| 文字が読みにくい | 「思い付き」（`#ca8a04`）の上の白い文字はコントラスト 2.94:1。読みやすさの目安（小さな文字で 4.5:1）に届かない |
| 色覚の多様性を未検証 | 色の違いが分かりにくい人でも見分けられるか、確かめていない |

色を検証済みのものに替え、チップを「色が見分けにくくても文字で分かる」形にする。

## ユーザーストーリー

- ユーザーとして、種別のチップを色でも文字でも見分けたい。
- ユーザーとして、「課題」がエラーのように見えないでほしい。

## 要件

### 機能要件

- [ ] FR-1: 種別の色を、配色の検証（色覚の違いでの見分けやすさ）を通した次の色に替える（Q-027）: 課題 = 紫 `#4a3aa7`、思い付き = 黄 `#eda100`、調査 = 緑青 `#1baf7a`（メモは灰色のまま）。
- [ ] FR-2: チップの見た目を、**薄い色の背景＋種別の色の点＋濃い文字** にする（Q-027）。文字の色は種別によらず濃い色にし、コントラスト 4.5:1 以上にする。
- [ ] FR-3: 完了チェックの枠と塗りの色も、新しい種別の色に合わせる（仕様002）。
- [ ] FR-4: 色の定義は今までどおり `kind.rs` の1か所だけ。フロントは `list_kinds` で受け取る。
- [ ] FR-5: 赤・緑など「良い・悪い」を表す色は、種別には使わない。

### 非機能要件

- NFR-1: 3色の組み合わせは、配色の検証スクリプトの「全組み合わせ」で色覚の違いの項目に合格する。
- NFR-2: チップの文字は、背景に対してコントラスト 4.5:1 以上。

## 受け入れ条件

- [ ] AC-1: ホームと課題ページのチップが新しい色・見た目になる。「課題」は赤ではない。
- [ ] AC-2: チップの文字が、どの種別でも読みやすい（コントラスト 4.5:1 以上を検証スクリプトで確認）。
- [ ] AC-3: 3色の組み合わせが配色の検証に合格する（全組み合わせ）。
- [ ] AC-4: 完了チェックの色がチップの色と合っている。

## 画面・UI（案）

```
今:    [■課題| READMEを書く]        ← 赤い背景に白文字
案:    [● 課題  READMEを書く]        ← 薄い紫の背景、紫の点、濃い文字
       [● 思い付き  付箋っぽく表示]  ← 薄い黄の背景、黄の点
       [● 調査  ランタイムを調べる]  ← 薄い緑青の背景、緑青の点
```

## データ・API

- `kind.rs` の `color` を替えるだけ。DB・コマンドの変更なし。
- 検証の結果（候補A、白背景）:

  | 項目 | 結果 |
  | --- | --- |
  | 色覚の違いでの差（全組み合わせ） | 合格（最小 ΔE 9.1、目安 8 以上） |
  | 通常の見え方での差 | 合格（最小 ΔE 22.9） |
  | 背景とのコントラスト | 黄・緑青は 3:1 未満 → **文字のラベルを必ず付ける**（チップは常に文字付きなので満たす） |

## 注意点

- 課題ページでは、グラフの「完了」のオレンジ（`#eb6834`）と、候補Aの「思い付き」の黄（`#eda100`）が同じ画面に並ぶ。通常の見え方でも近い色（ΔE 13.7）だが、チップは常に文字付き、グラフは凡例付きなので、取り違えは起きにくい。気になる場合は Q-027 で別の候補を選ぶ。
