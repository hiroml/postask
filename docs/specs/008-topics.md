# 008: 話題（ポストの話題への振り分け）

## 背景・目的

ポストが増えると、「どのテーマに関するやることか」でまとめて見たくなる。
課題の概要をポストして「話題」を作り、その後のポストがどの話題に当たるかを AI が判別して振り分ける（B-017）。

話題は、話題のプレビュー（B-018）、話題の検索・ランキング（B-027）、課題ページの話題ごとの集計（B-003 の残り）の土台になる。
この仕様では **話題を作る・ポストを振り分ける・話題の一覧を見る** までを作る。

## ユーザーストーリー

- ユーザーとして、「x-clone の開発」のような取り組みを話題として作りたい。
- ユーザーとして、ポストするたびに手で話題を選ばなくても、AI に振り分けてほしい。
- ユーザーとして、ポストがどの話題に入ったかをタイムラインで見たい。
- ユーザーとして、AI の振り分けが間違っていたら外したい。

## 要件

### 話題を作る

- [ ] FR-1: 話題は「名前」と「概要」を持つ。名前は1〜20文字で、同じ名前の話題は作れない。
- [ ] FR-2: 話題は次の2つの方法で作れる（Q-028）。
  - **入力欄から**: 入力欄の「# 話題として投稿」を選んでポストすると、その本文を概要として話題を作る。名前は AI が提案し、作成前に確認・修正できる。
  - **話題ページから**: 「話題を作る」から名前と概要を入力して作る（ポストはしない）。
- [ ] FR-3: 話題として投稿した本文も、普段のポストと同じくタイムラインに出す（「# 話題を作成」の印付き）。タスクへの分類はしない。

### 振り分け

- [ ] FR-4: ポストの分類（仕様001）のときに、既存の話題の一覧（名前と概要）も AI に渡し、そのポストが当たる話題を 0〜3 個選ばせる。当たらなければ 0 個。
- [ ] FR-5: 振り分けはポスト単位（Q-029）。タスクはポストの話題を引き継ぐ（課題ページなどでタスクの話題を見るときは、そのポストの話題を使う）。
- [ ] FR-6: 話題を作ったとき、既存のポストの直近100件を、1回の AI 呼び出しでまとめて振り分け直す（Q-030）。裏で行い、終わったら該当するポストに話題のチップが付く。
- [ ] FR-7: 話題が1つも無いときは、今までどおりの分類だけを行う（話題の判定はしない）。

### 表示・修正

- [ ] FR-8: タイムラインのポストに、話題のチップ（`# 話題名`）を出す。タスクのチップとは見た目を分ける（枠線だけ・灰色）。
- [ ] FR-9: 話題のチップの「×」で、そのポストから話題を外せる。外した話題は、再分類しても自動では付け直さない。
- [ ] FR-10: 話題ページ（`/topics`、仕様005 で準備中）に、話題の一覧を出す。各話題に名前・概要・ポスト数・未完了のタスク数を表示する。話題を押したときのプレビュー（ポストの一覧など）は B-018 で作る。
- [ ] FR-11: 話題ページから話題の名前・概要を編集、削除できる。削除しても、ポストとタスクは消えない（振り分けだけ消える）。

### 非機能要件

- NFR-1: 話題が増えても、分類1回の AI の料金が大きく増えないよう、AI に渡す話題は最大50件（最近使われた順）にする。
- NFR-2: 話題の判定が失敗しても、タスクへの分類は失敗扱いにしない（振り分けなしで保存する）。

## 受け入れ条件

- [ ] AC-1: 「x-clone の開発: Tauri と Leptos で作るタスク管理アプリ」を話題として投稿すると、AI が名前（例: 「x-clone の開発」）を提案し、確認して話題ができる。
- [ ] AC-2: 話題を作った後に「ナビゲーターのページを増やす」とポストすると、その話題のチップが付く。
- [ ] AC-3: 話題と関係ないポスト（例: 「今日は眠い」「牛乳を買う」）には話題が付かない。
- [ ] AC-4: 話題のチップの × で外すと、そのポストから話題が消え、再起動しても戻らない。
- [ ] AC-5: 話題ページに、話題ごとのポスト数・未完了のタスク数が出る。
- [ ] AC-6: 話題を削除しても、ポストとタスクは残る。
- [ ] AC-7: 話題を作ると、既存のポスト（直近100件）のうち当たるものに話題が付く。話題ページから作った場合も同じ。
- [ ] AC-8: 振り分けの処理の単体テストが、モックのプロバイダで通る（話題なし・1つ・複数・外した話題を付け直さない・判定失敗でも分類は成功）。
- [ ] AC-9: 話題ページの「話題を作る」で名前と概要を入力して作れる。このときタイムラインにはポストが増えない。

## 画面・UI

```
┌ 入力欄 ───────────────────────────────┐
│ x-clone の開発: Tauri と Leptos で…     │
│ [ポスト ▾]  ← 「ポスト」/「# 話題として投稿」を選べる │
└───────────────────────────────────────┘
       ↓ 話題として投稿
┌ 話題を作成 ───────────────┐
│ 名前: [x-clone の開発    ]  │ ← AI の提案。直せる
│ 概要: Tauri と Leptos で…   │
│          [キャンセル] [作成] │
└───────────────────────────┘

タイムライン:
│ ナビゲーターのページを増やす            │
│ [○ 課題 | ページを増やす]               │
│ ( # x-clone の開発 × )                  │ ← 話題のチップ（枠線だけ・灰色）

話題ページ:
│ # x-clone の開発        ポスト 12 / 未完了 5 │
│   Tauri と Leptos で作るタスク管理アプリ   [編集] │
```

## データ・API

### DB（マイグレーション 版4）

```sql
CREATE TABLE topics (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT    NOT NULL UNIQUE,
  description TEXT    NOT NULL DEFAULT '',
  source_post_id INTEGER REFERENCES posts(id) ON DELETE SET NULL,  -- 話題として投稿したポスト
  created_at  TEXT    NOT NULL
);

CREATE TABLE post_topics (
  post_id     INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  topic_id    INTEGER NOT NULL REFERENCES topics(id) ON DELETE CASCADE,
  assigned_by TEXT    NOT NULL,          -- 'ai' | 'user'
  removed     INTEGER NOT NULL DEFAULT 0, -- 1 = ユーザーが外した（AI が付け直さない）
  created_at  TEXT    NOT NULL,
  PRIMARY KEY (post_id, topic_id)
);

ALTER TABLE posts ADD COLUMN kind TEXT NOT NULL DEFAULT 'post';  -- 'post' | 'topic'（話題として投稿したもの）
```

### AI（分類の拡張）

- 分類の出力（構造化出力）に `topic_ids: [整数]` を足す。システムプロンプトに話題の一覧（id・名前・概要）を渡す。
- 返ってきた id のうち、存在しないもの・外されたものは捨てる。
- 話題の名前の提案（FR-2）: 話題の本文から、20文字以内の名前を1つ提案させる（`LlmProvider::suggest_topic_name`）。
- 既存ポストの振り分け直し（FR-6、Q-030）: 新しい話題と直近100件のポスト本文を1回で渡し、当たるポストの id を返させる（`LlmProvider::match_posts_to_topic`）。

### Tauri コマンド

| コマンド | 内容 |
| --- | --- |
| `suggest_topic_name(body)` | 話題の名前の提案 |
| `create_topic(name, description, body: Option)` | 話題を作る。`body` があれば話題として投稿したポストも保存（入力欄から）。無ければ話題だけ（話題ページから）。どちらも振り分け直しを裏で始める |
| `list_topics()` | 話題の一覧（ポスト数・未完了のタスク数つき） |
| `update_topic(id, name, description)` / `delete_topic(id)` | 編集・削除 |
| `remove_post_topic(post_id, topic_id)` | ポストから話題を外す |

- `PostWithTasks` に `topics: Vec<TopicRef>`（id・名前）を足す。

## スコープ外

- 話題のプレビュー（話題を押したときのポスト一覧・課題数、B-018）
- 話題の検索・ランキング（B-027）
- 課題ページの話題ごとの集計（B-003 の残り。この仕様の後で追加）
- 手で話題を付ける（外すのはこの仕様で作る。付けるのは B-004 と合わせて検討）
- ハッシュタグ（本文に `#名前` と書いて話題を付ける）
