# 002: タスクを完了にする

## 背景・目的

仕様001でポストからタスクが作られるようになったが、タスクを「終わった」にする操作が無く、
やることとやったことの区別が付かない。タスクを完了・未完了に切り替えられるようにし、
タイムライン上で残っているタスクが一目で分かるようにする。

DB の `tasks.status`（`open` / `done`）は仕様001で用意済みなので、主に画面とコマンドの追加になる。

## ユーザーストーリー

- ユーザーとして、終わったタスクをワンクリックで完了にしたい。残りのやることだけに集中したいから。
- ユーザーとして、間違えて完了にしたタスクを元に戻したい。

## 要件

### 機能要件

- [ ] FR-1: タスクチップの先頭にチェックボックス（○）を表示する。クリックすると完了（✓）になり、もう一度クリックすると未完了に戻る。
- [ ] FR-2: 完了したタスクのチップは、タイトルに取り消し線を引き、色を薄くする。
- [ ] FR-3: 完了状態は DB に保存し、アプリを再起動しても保たれる。
- [ ] FR-4: 切り替えは画面上ですぐ反映する。保存に失敗したら元の状態に戻し、エラーを表示する。
- [ ] FR-5: 完了にしたときに完了日時を記録し、未完了に戻したら消す（Q-014）。完了したチップにマウスを乗せると「完了: MM/DD HH:MM」と表示する。
- [ ] FR-6: 既存の DB（仕様001で作ったデータ）を、起動時に自動で新しい形（`completed_at` 列あり）に更新する。データは失われない。

### 非機能要件

- NFR-1: クリックしてから表示が切り替わるまで 100ms 以内（保存の完了は待たない）。

## 受け入れ条件

- [ ] AC-1: タスクチップの ○ をクリックすると ✓ になり、タイトルに取り消し線が付いて色が薄くなる。
- [ ] AC-2: 完了したタスクの ✓ をもう一度クリックすると、未完了の表示に戻る。
- [ ] AC-3: 完了にしてからアプリを再起動しても、完了のまま表示される。
- [ ] AC-4: 1つのポストに複数のタスクがあるとき、クリックしたタスクだけが切り替わる。
- [ ] AC-5: 存在しないタスク ID で完了にしようとすると、エラーになり DB は変わらない（単体テスト）。
- [ ] AC-6: 完了にすると `completed_at` に日時が入り、未完了に戻すと空になる（単体テスト）。完了したチップにマウスを乗せると完了日時が出る。
- [ ] AC-7: 仕様001の時点の DB（`completed_at` 列が無い）でアプリを起動すると、列が追加され、既存のポスト・タスクがそのまま表示される（単体テスト＋手動確認）。
- [ ] AC-8: 更新済みの DB で再起動しても、更新処理が二重に走らない（単体テスト）。

## 画面・UI

```
│ READMEを書く、あとCIも設定する              │
│ [○ 課題 | READMEを書く]  [✓ 課題 | CIを設定する] │  ← 右は完了（取り消し線・薄い色）
```

- チェックボックスはチップ内の左端に置く。チップ全体ではなく ○/✓ の部分だけがクリック対象（誤操作を防ぐ）
- キーボード操作: チェックボックスにフォーカスして Space / Enter で切り替え

## データ・API

### DB

- 既存の `tasks.status`（`open` / `done`）を使う。
- `tasks.completed_at TEXT`（完了日時。未完了なら NULL）を追加する（Q-014）。

#### マイグレーション（DB の形を更新する仕組み。バックログ B-012 の最小版）

- SQLite の `PRAGMA user_version` に「DB の版数」を記録する。起動時に版数を見て、足りない更新だけを順番に当てる。
- 更新は番号付きの一覧としてコードに持つ。1件ずつトランザクションで当て、成功したら版数を上げる。

| 版 | 内容 |
| --- | --- |
| 1 | 仕様001のスキーマ（posts / tasks）。既存の DB（版数 0 だがテーブルあり）もここから始める |
| 2 | `ALTER TABLE tasks ADD COLUMN completed_at TEXT` |

- 今後のテーブル・列の追加（仕様003の `replies` など）も、この一覧に版を足して行う。

### Tauri コマンド

```rust
#[tauri::command(rename_all = "snake_case")]
fn set_task_status(task_id: i64, status: TaskStatus) -> Result<PostWithTasks, String>;
// TaskStatus: "open" | "done"。戻り値はそのタスクを含むポスト全体（画面の更新に使う）
```

- 存在しない `task_id` は `TaskNotFound` エラー。
- `tasks.status` を文字列から `TaskStatus` 型（enum）に変える（不正な値を防ぐため）。JSON の形は変わらない。

## スコープ外

- 完了したタスクを隠す・絞り込む表示（必要ならバックログに起票）
- タスクの削除・編集（B-004）
- 完了数などの集計・可視化（B-003）

## 注意点

- 分類の再試行（`retry_classification`）はタスクを作り直すため、完了状態は失われる。
  ただし再試行できるのは分類に失敗したポスト（タスクが無い）だけなので、現状は問題にならない。
