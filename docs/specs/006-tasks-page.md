# 006: 課題ページ（集計・グラフ・一覧）

## 背景・目的

ポストからタスクが溜まってきたが、今はタイムラインを遡らないと「何がどれだけ残っているか」「どれだけ片付けたか」が分からない。
コンセプトの「課題が多いほど、その人のやること・価値を見出せるように可視化する」（overview F3）の最初の形として、
**種別ごとの数・完了の進み具合・推移を1ページで見られる「課題」ページ**を作る。

仕様005のナビゲーターの「✅ 課題」（`/tasks`）の中身にあたる。話題ごとの集計は、話題（B-017）ができてから追加する。

## ユーザーストーリー

- ユーザーとして、未完了のタスクがどれだけあるか、ひと目で知りたい。
- ユーザーとして、課題・思い付き・調査のどれが多いか、どれだけ片付いたかを見たい。
- ユーザーとして、最近タスクが増えているのか片付いているのか、流れを見たい。
- ユーザーとして、残っているタスクを一覧で見て、その場で完了にしたい。

## 要件


### 絞り込み（ページ上部の1行）

- [ ] FR-1: ページの一番上に、絞り込みを1行で並べる。**期間**（全期間 / 直近7日 / 直近30日 / 直近90日、初期値は全期間）、**種別**（すべて / 課題 / 思い付き / 調査）、**状態**（すべて / 未完了 / 完了）。
- [ ] FR-2: 絞り込みは、その下の数字・グラフ・一覧すべてに効く（数字どうしが食い違わない）。
- [ ] FR-3: 絞り込みを変えて読み込み直す間は、前の表示を薄くして残す（表示が一瞬消えたり、がたついたりしない）。

### 数字のタイル（3つ）

- [ ] FR-4: 大きな数字で3つ並べる。
  - **未完了**: 対象タスクのうち未完了の数
  - **完了**: 対象タスクのうち完了の数
  - **完了率**: 完了 ÷ 対象タスク（%、小数点以下切り捨て）。対象が0件なら「—」
  - 「対象タスク」= 作成日時が期間内で、種別・状態の絞り込みに合うタスク

### グラフ1: 種別ごとの課題数

- [ ] FR-5: 種別ごとの横向きの積み上げ棒グラフ。1本の棒 = 1種別、棒の中を **未完了** と **完了** に分ける。
- [ ] FR-6: 棒の右に「未完了 8 / 完了 3」のように数を書く（色だけに頼らない）。凡例（未完了・完了）を上に置く。
- [ ] FR-7: 棒の部分にマウスを乗せる（またはキーボードでフォーカスする）と、種別・状態・数をツールチップで表示する。
- [ ] FR-8: 棒をクリックすると、その種別で絞り込む（FR-1 の種別が切り替わる）。

### グラフ2: 推移

- [ ] FR-9: 作成数と完了数の推移を、2本の折れ線で表示する（縦軸は1本＝件数）。
  - 期間が直近7日・30日なら **日ごと**、直近90日・全期間なら **週ごと**（月曜始まり）に数える
  - 全期間のときは、最初のタスクがある週から今週まで
  - 作成数 = その日（週）に作られたタスクの数、完了数 = その日（週）に完了したタスクの数
- [ ] FR-10: グラフ上でマウスを動かすと、縦の線が一番近い日（週）に合い、その日の作成数・完了数をまとめて表示する。
- [ ] FR-11: 線の端に「作成」「完了」と直接ラベルを付け、凡例も置く。

### 表で見る

- [ ] FR-12: 各グラフに「表で見る」ボタンを付け、押すとグラフと同じ数字を表で表示する（グラフが見づらい人・コピーしたいとき用）。

### 課題の一覧

- [ ] FR-13: グラフの下に、対象タスクの一覧を表で出す。列: 完了チェック / 種別（今のチップ） / タイトル / 元のポスト（先頭30文字、マウスを乗せると全文） / 作成日 / 完了日。
- [ ] FR-14: 並び順は「未完了が先、その中で新しい順」。完了は完了日の新しい順。
- [ ] FR-15: 一覧の完了チェックはホームと同じ動き（仕様002）。切り替えると、数字・グラフもすぐ更新し、ホームのタイムラインにも反映される。
- [ ] FR-16: 一度に出すのは500件まで。超えるときは「新しい500件を表示しています」と出す。

### その他

- [ ] FR-17: タスクが1件も無いときは、グラフの代わりに「まだタスクがありません。ホームでポストすると、ここに集計されます」と出す。
- [ ] FR-18: 日付の区切り（日ごと・週ごと）は、パソコンのタイムゾーン（日本時間）で数える。

### 非機能要件

- NFR-1: タスク1,000件で、ページを開いてから表示まで 500ms 以内。
- NFR-2: 集計はバックエンド（SQLite）で行い、フロントは受け取った数字を描くだけにする（計算の食い違いを防ぎ、単体テストしやすくする）。
- NFR-3: グラフの色（未完了・完了の2色）は、色覚の多様性に配慮した配色の検証（dataviz スキルの検証スクリプト）を通したものを使う。

## 受け入れ条件

- [ ] AC-1: 課題ページを開くと、数字3つ・種別ごとの棒グラフ・推移の折れ線・一覧が出る。
- [ ] AC-2: 数字が一覧の件数と一致する（未完了＋完了＝一覧の件数、500件以下のとき）。
- [ ] AC-3: 期間・種別・状態を変えると、数字・グラフ・一覧がそろって変わる。
- [ ] AC-4: 種別の棒をクリックすると、その種別で絞り込まれる。
- [ ] AC-5: 棒・折れ線にマウスを乗せると値が出る。キーボードのフォーカスでも出る。

- [ ] AC-7: 一覧でタスクを完了にすると、未完了が1減り完了が1増える。ホームに戻ると、そのタスクが完了になっている。

### グラフの見た目（dataviz スキルの方針）

- **色**: 未完了・作成 = 青（`#2a78d6`）、完了 = オレンジ（`#eb6834`）。どちらのグラフでも「完了」は同じ色にする。
  赤・緑などの「良い・悪い」を表す色は使わない。実装時に配色の検証スクリプトを通し、通らなければ近い色に調整する。
- **文字**: 数値・ラベル・凡例は黒・灰の文字色で書き、系列の色は使わない（色は棒・線・凡例の印だけ）。
- **棒**: 細めの棒、端は角丸4px、未完了と完了の間に2pxのすき間。
- **線**: 太さ2px。点は8px以上。
- **目盛り・補助線**: 薄い灰色で控えめに。縦軸は0から始める。
- **ツールチップ**: 数値を太く大きく、系列名は小さく。系列は短い線の印で示す。
- **ダークモード**: アプリ自体に無いので対象外。

## データ・API

### Tauri コマンド

```rust
#[tauri::command(rename_all = "snake_case")]
fn get_task_dashboard(
    period: Period,                 // "all" | "7d" | "30d" | "90d"
    kind: Option<TaskKind>,         // None = すべて
    status: Option<TaskStatus>,     // None = すべて
) -> Result<TaskDashboard, String>;
```

```rust
struct TaskDashboard {
    totals: Totals,                 // open, done, completion_rate（0〜100 の整数。対象0件なら None）
    by_kind: Vec<KindCount>,        // kind, open, done（タスクにする種別すべて。0件の種別も含める）
    trend: Trend,                   // bucket: "day" | "week", points: [{ start: "2026-09-22", created, completed }]
    tasks: Vec<TaskRow>,            // task（今の Task）と post_body。最大500件
    truncated: bool,                // 500件を超えたか
}
```

- 一覧のチェックは既存の `set_task_status` を使う。結果の `PostWithTasks` でホームの共有状態を更新し、そのあと `get_task_dashboard` を呼び直す。
- 集計は SQL（`GROUP BY`）で行う。日付の区切りはローカル時刻（`chrono::Local`）で計算する。

### DB

- 変更なし（既存の `tasks.created_at` / `completed_at` / `status` / `kind` を使う）。
- 1,000件を超えて遅くなるようなら、`tasks(created_at)` などに索引を足す（マイグレーション）。

### フロントエンド

- `src/pages/tasks.rs`（仕様005で作る枠に中身を入れる）
- `src/components/charts/`（新規）: 棒グラフ・折れ線・ツールチップ・表表示。グラフ用のクレートは使わず、Leptos で SVG を直接描く（Q-025）

## 関連して見つけた課題

- 今のタスクチップは「課題」を**赤**で表示している。赤は一般に「エラー・危険」を表すため、種別の色としては紛らわしく、色覚の多様性の検証もしていない。
  この仕様のグラフでは種別を色分けしない（種別は棒の行ラベルで示す）ので影響しないが、チップの色の見直しをバックログ B-030 に起票した。
