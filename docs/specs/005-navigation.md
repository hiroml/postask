# 005: ナビゲーター（ページ構成とメニュー）

## 背景・目的

今のアプリはホーム（入力欄とタイムライン）の1画面だけ。課題ページ（B-003）、プロフィール（B-015）、通知（B-026）、
話題の検索（B-027）、設定（B-006）など、ページを増やす要望が続いている。
その土台として、**ページを切り替えるメニュー（ナビゲーター）** を作る。

この仕様では「メニューとページの切り替え」までを作り、各ページの中身はそれぞれの仕様で作る（課題ページは仕様006）。
ページ構成・配置などは [素案](../proposals/B-025-navigation.md) をもとに、Q-018〜Q-022 の回答で確定させる。

## ユーザーストーリー

- ユーザーとして、ホーム・課題・設定などのページを、メニューからすぐ行き来したい。
- ユーザーとして、今どのページにいるかが一目で分かってほしい。
- ユーザーとして、別のページから戻ったとき、ホームのタイムラインが最初から読み込み直しにならず、そのまま見たい。

## 要件

### 機能要件

以下は素案どおりの場合。Q-018〜Q-022 の回答で変わる箇所は（Q-xxx）と書いている。

- [ ] FR-1: 画面の左にメニューを置く（Q-019）。項目は 🏠 ホーム / ✅ 課題 / # 話題 / 🔔 通知 / 👤 プロフィール / ⚙ 設定（Q-018, Q-020）。
- [ ] FR-2: 今いるページのメニュー項目を強調表示する（背景色と太字）。
- [ ] FR-3: メニューの一番下にアカウントメニュー（アイコン・名前・「⋯」）を置く。クリックでポップアップが開き、プロフィール・設定へ移動できる。ログアウトは B-016（アカウント）を作るまで出さない。名前は当面「自分」の固定表示（B-015 / B-024 で設定できるようにする）。
- [ ] FR-4: ウィンドウの幅が 1000px 以上ならアイコン＋文字、未満ならアイコンだけのメニューにする。アイコンだけのときは、マウスを乗せると名前を表示する。
- [ ] FR-5: 中身がまだ無いページ（素案では 話題・通知・プロフィール・設定）の扱いは Q-022 に従う。出す場合は「準備中」と、そのページで何ができるようになる予定か（関連するバックログ ID）を表示する。
- [ ] FR-6: ページを移動しても、ホームの状態（タイムライン、読み込み済みのページ、入力中の下書き）を保つ。裏で届いた分類・AI リプライの結果も、ホームに戻ったときに反映されている。
- [ ] FR-7: メニューはキーボードでも操作できる（Tab で移動、Enter で開く）。アカウントメニューは Esc で閉じる。
- [ ] FR-8: ウィンドウの既定の大きさを 1100×760 にし、最小を 720×560 にする。

### 非機能要件

- NFR-1: ページの切り替えは 100ms 以内に表示が変わる（通信を待たない）。
- NFR-2: 今あるホームの機能（ポスト、分類、完了、AI リプライ）の動きは変えない。

## 受け入れ条件

- [ ] AC-1: 起動するとホームが開き、メニューの「ホーム」が強調されている。
- [ ] AC-2: メニューの各項目をクリックするとそのページに切り替わり、強調表示も移る。
- [ ] AC-3: ホームでタイムラインをスクロール・「さらに読み込む」した後、課題ページへ行ってホームに戻ると、読み込み済みのポストがそのまま表示される（最初から読み込み直さない）。
- [ ] AC-4: ホームで「AI に聞く」を押してすぐ課題ページへ移動し、数秒後にホームへ戻ると、リプライが表示されている。
- [ ] AC-5: ウィンドウ幅を 1000px 未満にするとアイコンだけのメニューになり、マウスを乗せると名前が出る。
- [ ] AC-6: アカウントメニューを開くとプロフィール・設定があり、ログアウトは無い。Esc やメニューの外のクリックで閉じる。
- [ ] AC-7: キーボードだけでメニューを移動し、ページを開ける。
- [ ] AC-8: 中身の無いページが Q-022 の回答どおりに扱われる。

## 画面・UI

素案の「画面のイメージ」を参照（[proposals/B-025-navigation.md](../proposals/B-025-navigation.md)）。

- メニューの幅: 文字あり 220px / アイコンだけ 72px
- 強調表示: 今のナビの色（`#eaf3ff` の背景、`#1d4ed8` の文字）を使う
- ページのヘッダー: 各ページの上にページ名（今の「ホーム」の見出しと同じ形）

## データ・API

### ページの切り替え

- Leptos 公式のルーター `leptos_router`（Leptos 0.8 対応版）を使う。**依存クレートの追加は Q-024 で承認をもらう**。
- パス:

  | パス | ページ | 中身 |
  | --- | --- | --- |
  | `/` | ホーム | 今の画面 |
  | `/tasks` | 課題 | 仕様006 |
  | `/topics` | 話題 | 準備中（B-017, B-018, B-027） |
  | `/notifications` | 通知 | 準備中（B-026） |
  | `/profile` | プロフィール | 準備中（B-015, B-024） |
  | `/settings` | 設定 | 準備中（B-006 など）。Q-021 の回答を「予定」として表示 |
  | それ以外 | ホームへ移動 | |

### 画面の構成（フロントエンド）

- `src/app.rs`: ルーターとレイアウト（メニュー＋ページ）だけにする
- `src/components/nav.rs`（新規）: メニューとアカウントメニュー
- `src/pages/`（新規）: `home.rs`（今の画面を移す）、`tasks.rs`（仕様006）、`coming_soon.rs`（準備中）
- タイムラインの状態（ポスト一覧・種別・イベントの購読）は、ページの外（アプリ全体の共有状態）に置く。これで FR-6 を満たす

### バックエンド・DB

- 変更なし（ウィンドウの大きさの設定 `tauri.conf.json` のみ）

## スコープ外

- 各ページの中身（課題ページは仕様006、ほかは各バックログ項目）
- ログアウト・アカウントの切り替え（B-016、Q-013 で保留）
- 通知の未読バッジ（B-026）
- ダークモード
