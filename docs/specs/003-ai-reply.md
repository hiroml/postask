# 003: AI リプライ

## 背景・目的

ポストがタスクに分類されるようになったが、「次に何をすればいいか」はユーザーが自分で考える必要がある。
AI がポストにリプライ（返信）する形で、調査の進め方や簡単な解決方針を返し、着手のハードルを下げる（overview F4）。

将来、他人からのリプライ（B-019、Q-013 で保留中）を追加するときも同じ仕組みを使えるよう、リプライは「誰が書いたか」を持つデータにしておく。

## ユーザーストーリー

- ユーザーとして、「〇〇を調べたい」とポストしたら、調べ方（キーワードや見るべき情報源）を教えてほしい。
- ユーザーとして、「〇〇を直す」とポストしたら、解決の方針や最初の一歩を提案してほしい。
- ユーザーとして、AI の返信がいまいちだったら、もう一度聞き直したい。

## 要件

### 機能要件

- [ ] FR-1: AI がポストにリプライを1件書く。1つのポストに対する AI のリプライは1件まで（聞き直すと置き換わる）。
- [ ] FR-2: リプライの内容は、そのポストのタスクの種別に合わせる。
  - 課題（`issue`）: 解決の方針と、最初にやること（3〜5ステップ程度）
  - 調査（`research`）: 調べ方（検索キーワード、見るべき情報源、比較の観点）と、分かっている範囲の概要
  - 思い付き（`idea`）: 実現のアイデアと、小さく試す方法
  - メモのみ（`note`）のポストにはリプライしない
- [ ] FR-3: リプライを書くタイミングは Q-015 の回答に従う。
- [ ] FR-4: 「AI に聞く」ボタン（まだリプライが無いとき）と「聞き直す」ボタン（あるとき）を用意する。
- [ ] FR-5: 生成中は「🤖 AI が考え中…」、失敗したら「リプライを作れませんでした」と再試行ボタンを表示する。ポストや分類には影響しない。
- [ ] FR-6: リプライはポストの下に、ポスト本体と区別できる見た目（左に線、🤖 AI の表示）で出す。
- [ ] FR-7: リプライは DB に保存し、再起動後も表示される。
- [ ] FR-8: リプライ用のモデルは分類とは別に設定できる（`.env` の `CLAUDE_REPLY_MODEL`）。既定値は Q-016 の回答に従う。
- [ ] FR-9: Web 検索を使うかは Q-017 の回答に従う。

### 非機能要件

- NFR-1: リプライの生成中もポスト・分類・タスクの完了などの操作はふつうにできる。
- NFR-2: AI に送るのは、そのポストの本文と分類済みのタスク（種別・タイトル）だけ。
- NFR-3: ポスト本文に指示が書かれていても従わない（本文はあくまで相談の内容として扱う）。
- NFR-4: リプライは400〜800文字程度のプレーンテキスト（Markdown の記号は使わず、箇条書きは「・」）。

## 受け入れ条件

- [ ] AC-1: 「Rust の非同期ランタイムの違いを調べたい」に対し、検索キーワードや比較の観点を含むリプライが付く。
- [ ] AC-2: 「ログイン画面のバリデーションを直す」に対し、方針と最初のステップを含むリプライが付く。
- [ ] AC-3: 「今日は眠い」（メモのみ）にはリプライが付かず、「AI に聞く」ボタンも出ない。
- [ ] AC-4: 「聞き直す」を押すと、古いリプライが新しいものに置き換わる。
- [ ] AC-5: API キーが無いときは「リプライを作れませんでした」と再試行ボタンが出て、ポストとタスクはそのまま残る。
- [ ] AC-6: 再起動後もリプライが表示される。
- [ ] AC-7: リプライ生成中にも、別のポストの投稿やタスクの完了ができる。
- [ ] AC-8: リプライ処理の単体テストが、Claude API を呼ばないモックのプロバイダで通る。

## データ・API

### DB

新しいテーブルを追加する（既存テーブルの変更は無いので、マイグレーションは不要）。

```sql
CREATE TABLE IF NOT EXISTS replies (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  post_id    INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  author     TEXT    NOT NULL,          -- 'ai'（将来 他人のリプライ用にユーザーを入れられる）
  body       TEXT    NOT NULL DEFAULT '',
  model      TEXT,                      -- 生成したモデル名（AI のみ）
  status     TEXT    NOT NULL,          -- pending | done | failed
  error      TEXT,
  created_at TEXT    NOT NULL
);
```

- AI のリプライはポストごとに1件。聞き直すときは既存の AI リプライを置き換える。

### Tauri コマンド・イベント

```rust
#[tauri::command(rename_all = "snake_case")]
fn request_ai_reply(post_id: i64) -> Result<(), String>;   // 生成を裏で開始（聞き直し・再試行も同じ）
```

- `list_timeline` などで返す `PostWithTasks` に `replies: Vec<Reply>` を追加する。
- イベント名を `post-classified` から `post-updated` に変え、分類の完了とリプライの完了の両方で送る（payload は `PostWithTasks`）。

### AI 呼び出し

- `LlmProvider` トレイトに `reply(post_body, tasks) -> Result<String, LlmError>` を追加する（ADR-002 のとおり、ローカル LLM にも差し替え可能）。
- `ClaudeProvider`: リプライ用のモデルとパラメータ（`max_tokens`、effort、フォールバック）はモデルごとに決める（仕様001と同じ方式）。タイムアウトは60秒。
- 出力は構造化出力を使わず、text ブロックをそのまま本文にする。`stop_reason` の確認は仕様001と同じ。

## スコープ外

- 他人からのリプライ・リツイート（B-019、Q-013 で保留）
- リプライへの返信（会話のやり取り）
- リプライから新しいタスクを起こす（B-002 で検討）
- Markdown の表示
