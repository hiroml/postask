# 判断待ちボード

人に確認・決定してほしい事項の一覧です。AI は判断できないことをここに追加し、人が回答します。

## 使い方

**人**
1. 「回答待ち」の項目を読み、`回答:` に答えを書く（選択肢の記号だけでも、自由記述でもOK）
2. AI に「回答を反映して」と伝える（`/apply-answers`）

**AI**
- 新しい確認事項は「回答待ち」の末尾に、次の番号で追加する
- 回答された項目は、関連文書（仕様書など）に反映してから「決定済み」へ移す
- 設計に大きく影響する決定は `docs/decisions/` に ADR としても残す
- 回答の代わりに自分で決めてはいけない。推奨案は書いてよい

**優先度**: 🔴 これが決まらないと先に進めない / 🟡 実装前までに決めたい / 🟢 後で決めてもよい

項目の書き方:

```markdown
### Q-NNN 🔴 タイトル

- 関連: [仕様書など](specs/xxx.md)
- 背景: なぜ決める必要があるか
- 選択肢:
  - A. 〇〇
  - B. 〇〇
- AI の推奨: 〇（理由）
- 回答:
```

## 回答待ち

### Q-013 🟡 複数ユーザー（アカウント）に対応するか

- 関連: [バックログ](backlog.md) B-016（アカウント）、B-019（他人からのリプライ）、B-015（プロフィール）
- 背景: これまでは「個人利用・ログインなし」（Q-002）と決め、既存のログイン機能も削除した（Q-011）。
  アカウントや「他人からのリプライ」を実現するには、この前提を変える必要がある。どこまで広げるかで、作りと作業量が大きく変わる
- 選択肢:
  - A. **当面は個人利用のまま**。アカウント・他人からのリプライは保留し、AI からのリプライや派生課題など1人で完結する機能を先に作る
  - B. **同じ PC で複数アカウント**。ログインで切り替え、ユーザーごとに DB を分ける。他人とのやり取りはできない（サーバー不要）
  - C. **サーバーを立てて複数人で共有**。他人からのリプライ・リツイートができる。`backend/` にサーバーを作り、認証・同期・ホスティングが必要（大きな変更）
- AI の推奨: A（まず1人で使って価値を確かめる。C に進む場合も、A の間に作る機能はそのまま生かせるよう、データにユーザー ID を持たせる準備だけしておく）
- 回答:
