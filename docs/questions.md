# 判断待ちボード

人に確認・決定してほしい事項の一覧です。AI は判断できないことをここに追加し、人が回答します。

## 使い方

**人**
1. 「回答待ち」の項目を読み、`回答:` に答えを書く（選択肢の記号だけでも、自由記述でもOK）
2. AI に「回答を反映して」と伝える（`/apply-answers`）

**AI**
- 新しい確認事項は「回答待ち」の末尾に、次の番号で追加する
- 回答された項目は、関連文書（仕様書など）に反映してから「決定済み」へ移す
- 設計に大きく影響する決定は `docs/decisions/` に ADR としても残す
- 回答の代わりに自分で決めてはいけない。推奨案は書いてよい

**優先度**: 🔴 これが決まらないと先に進めない / 🟡 実装前までに決めたい / 🟢 後で決めてもよい

項目の書き方:

```markdown
### Q-NNN 🔴 タイトル

- 関連: [仕様書など](specs/xxx.md)
- 背景: なぜ決める必要があるか
- 選択肢:
  - A. 〇〇
  - B. 〇〇
- AI の推奨: 〇（理由）
- 回答:
```

### Q-023 🟡 開発用 DB の最初の中身

- 関連: [004 開発用 DB の分離](specs/004-dev-db.md)
- 背景: 開発版は `x-clone-dev.sqlite` を使うようにする。最初の中身をどうするか
- 選択肢:
  - A. 空で始める（普段使いのデータに一切触れない。動作確認用のポストは自分で入れる）
  - B. 開発用 DB が無いときだけ、普段使いの DB をコピーして始める（本物に近いデータで確認できる。コピー元は読むだけ）
  - C. 開発版を起動するたびに、普段使いの DB をコピーし直す（常に最新のデータで確認できるが、開発版で入れたデータは毎回消える）
- AI の推奨: B（実際のデータで課題ページのグラフなどを確認しやすく、マイグレーションもコピーで試せる。やり直したいときは `x-clone-dev.sqlite` を消せばまたコピーされる）
- 回答:

### Q-024 🔴 依存クレート `leptos_router` の追加

- 関連: [005 ナビゲーター](specs/005-navigation.md)

  - B. 追加しない（簡単な切り替えを自前で作る。ページが増えると管理が大変になる）

### Q-025 🟡 グラフの描き方

- 関連: [006 課題ページ](specs/006-tasks-page.md)
- 背景: 今回のグラフは横棒と折れ線の2種類で、形は単純
- 選択肢:
  - A. 自前で SVG を描く（依存クレートを増やさない。見た目・ツールチップ・キーボード操作を細かく作り込める。作る量は少し増える）

- AI の推奨: A（2種類なら自前で十分。見た目のルール（色・線の太さ・ツールチップ）を守りやすい）
