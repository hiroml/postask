# 004: 開発用 DB の分離 — 実装計画

## 方針

- どの DB ファイルを使うかを決める処理を、テストしやすい純粋な関数（入力: 環境変数の値・デバッグかどうか・フォルダ）にする。
- 初回コピーは「開発用 DB が無く、普段使いの DB がある」ときだけ行う。コピー元は開かず、ファイルとしてコピーするだけ。
- 開発版の表示（タイトル・印）は `app_info` コマンドでフロントに伝える。タイトルは起動時にバックエンドで設定する。

## タスク

- [ ] **T1: DB ファイルの決定と初回コピー**（FR-1, FR-2, FR-4, FR-5 / AC-3〜AC-5）
  - `db.rs`: `DbLocation`（`resolve_db_path(env_override, is_debug, data_dir)`）、`prepare_dev_db(dev_path, prod_path)`（無ければコピー）
  - `lib.rs`: 起動時に使う DB を決め、パスをターミナルに表示。開発版ならウィンドウのタイトルを「x-clone（開発版）」に
  - 単体テスト: 開発版 / リリース版 / 環境変数あり、初回コピーする / しない（既にある・コピー元が無い）、コピー元が変わらない

- [ ] **T2: 開発版の表示**（FR-3 / AC-1）
  - `app_info` コマンド（`{ dev, db_path }`）
  - 画面のヘッダーに「開発版」の印（005 でメニューが入ったらメニュー上部へ移す）

- [ ] **T3: 確認**（AC-1〜AC-5）
  - 自動: 単体テスト。手動: 人が `cargo tauri dev` で確認し、普段使いの DB の更新日時が変わらないことを見る

## リスク・懸念

- ユーザーの `cargo tauri dev` が動いている間は、T1 を保存した時点で開発版が開発用 DB に切り替わる（普段使いの DB はコピー元として読むだけ）。
